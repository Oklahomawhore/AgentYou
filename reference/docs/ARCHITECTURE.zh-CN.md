# 持续人格 Agent 架构设计

日期：2026-09-22。

## 1. 核心结论

Jev 是可替换的语义决策提供方，不是整个人格，也不是 Runtime。框架的持久身份存在于事件历史、信念、情绪、目标、记忆及行为约束的连续演化中。LLM 是表达、复杂推理和反思的执行器，不是持久状态的唯一真源。

推荐：保留现有 Rust/Tokio、Main/Work 和统一 ToolRuntime，新增 MindRuntime 模块、MindState 存储与 InitiativePolicy。不要为情绪、性格、思考各建一个互相争夺控制权的独立 Agent。

这套设计提供可观察的拟人行为，不主张证明主观体验，也不把公开资料模拟称为真正复制某人的意识。

## 2. Jev 事实边界

截至核实日期，官方模型是 `jev-1.13.0`，输入仅文本，可接受字符串、JSON 对象、文本数组。它不直接理解图片/声音/视频输入；桌面截图需先由视觉模型变成结构化证据。官方暂不提供客户专属 fine-tune/LoRA，人格通过 state、instructions、criteria 塑造。[S2]

API 原语是 Noul（yes 概率）、Choice（选项分布）、Score（有序等级的加权期望）。Choice/Score 的 confidence 是对概率分布形状的压缩统计量，Noul 没有单独 confidence。不能把 confidence=.9 理解为对当前用户准确率 90%。[S3][S4]

官方披露新模型架构、parallel sampler 和 RLCD，未在本次可核实资料中给出足以复现的网络细节、权重、训练集和奖励公式。不能因此断言“本质就是某种大小的 BERT”，也不能声称“绝非 Transformer”。本文用 `f(state, question, criteria) -> probabilities` 描述功能契约，不将假设画成官方内部网络。[S1][S5]

旧文本分类器早就能输出概率；BERT 分类头和零样本 NLI 方法都说明，非逐 token 生成与动态语义分类不是全新问题。Jev 的工程定位是通用语义决策、类型契约、概率接口与服务性能的组合。是否优于本地领域分类器必须对照测试。[S7][S8]

## 3. 总体架构

```text
授权 OS / Browser / Work / User / Timer 事件
             ↓
来源认证、字段授权、脱敏、合并、去重、有效期
             ↓
EventLog → ContextBuilder → immutable ContextSnapshot
             ↑                       ↓
        MindState              exact hard gates
             ↑                       ↓
        StateReducer      CandidateBuilder + Jev appraisal
             ↑                       ↓
     事实/反馈/工作结果 ← InitiativePolicy
                           ├─ WAIT / DEFER
                           ├─ REFLECT → existing WorkRuntime
                           ├─ PROPOSE_WORK → capability + budget checks
                           └─ SPEAK → Main LLM → grounded draft
                                                   ↓
                                  recheck epoch / consent / time / quota
                                                   ↓
                                      Outbox → ToolRuntime / UI
```

用户明确发消息 → Main 的正常对话路径，不让 proactive gate 决定是否回复用户。系统暂停仍然生效。已进入对话的正常轮次用 ConversationLease / dialogue_epoch 做轮次管理，不反复评估“是否发起”。

## 4. MindState 不是一个大 system prompt

| 状态 | 含义 | 更新方式 |
|---|---|---|
| IdentityCore | 原创/模拟身份、价值排序、风格、知识边界 | 显式配置、版本迁移 |
| Beliefs | 对世界和人物的可修正判断 | 带证据、归属、时效的提案 |
| Affect | valence / arousal / control 等模拟状态 | 有界 reducer + 时间衰减 |
| Drives | 好奇、创造、胜任、社交、履行承诺 | 事件与实际进展驱动、有预算上限 |
| Goals / Intentions | 想达成什么，下一步是什么 | Main/Work 提案，Runtime 审批 |
| Memory | 观察、经历、知识、反思、习惯 | 按类型分存，来源与删除可追踪 |
| SelfModel | 对自身能力、偏好、错误模式的总结 | 证据充分时慢速修订 |

权限、暂停、预算上限不是人格可修改的字段。角色再好奇也不能越权读取文件；再不满也不能拒绝被关闭。

用情绪影响内容排序、表达强度、探索倾向和反思频率，而不是只在提示词里加“你现在很开心”。行为上必须能测到同一事件在不同状态下的差异；硬约束必须不变。

一个可用但不声称符合神经科学的动力学：

`emotion_next = clip(baseline + (emotion - baseline)*exp(-dt/tau) + W*appraisal)`

Jev 输出事件是否促进目标、是否意外等 appraisal；代码做时钟计算、衰减、取值裁剪、幂等和提交。具体矩阵和时间常数须评测。反思只能提案，不能绕过 reducer 改所有人格参数。

## 5. 四类主动性，而非一种通知

1. TaskUpdate：用户承诺/任务的进展、阻塞或结果。
2. PersonalDiscovery：角色围绕自己的预授权兴趣，实际探索后获得的新发现。
3. CuriosityQuestion：因真实知识缺口产生的开放问题。
4. SocialCheckIn：双方明确允许的轻量社交联系。

四类分别设 consent、候选来源、频率、冷却和效用准则。任务紧急不自动证明可以打断 DND；“角色想聊天”不自动构成用户愿意聊天。真正的独立性应体现为持续自己的研究或创作，而不是对不回复的用户施加愧疚。

若无候选/无到期意图，则休眠，不调用 LLM 编造“现在该想什么”。低频反思可以生成未来候选，但必须消耗独立预算并引用真实证据。定时条件仍通过既有 `work.create(activation=immediate|schedule|event|condition)` 统一，不新增公开 trigger facade。

## 6. Jev 问什么

建议把复合问题拆为：候选价值、与兴趣/目标相关性、新颖性、打扰风险、证据是否充分，以及影响情绪的目标一致性/意外程度。不要只问一句“我是不是应该说话”。

并行问题是独立评估，不是前一题的输出成为后一题输入，也不意味着它们统计独立。官方列有同义/否定题、Noul/Choice 之间不满足预期一致性的例子。[S6] 因此不要把多个 p 相乘当联合概率，明确的互补关系与枚举合法性由代码约束。

示例门控：允许且未超限；证据充分；候选有新增价值；打扰风险低；最后再对语义因子加权。示例权重用于跑通，不可宣称已经校准。高不确定性通常 WAIT；只有高潜在价值、可通过取证消除的不确定性才升级一个受预算约束的 REFLECT Work。

## 7. “思想”的可实现形式

ThoughtRecord 应记录：触发事件、观察证据、假设、备选解释、暂定结论、置信度、需要验证的问题、关联目标。它是审计用结论摘要，不是模型的隐私思维链，也不是凭空拥有的生活记忆。

Generative Agents 工作提供了“观察—记忆—反思—计划”的公开技术参照，但本文把环境改为真实授权的电脑事件、工具结果和个人工作区。[S10]

记忆至少区分：

- `observed_episode`：数字角色真正通过已授权环境见过/做过的事。
- `source_knowledge`：读过的材料，附来源、时间、权利与可信程度。
- `belief`：可修正、可矛盾的判断，不提升为世界事实。
- `reflection`：从经历推导出的总结，保留证据链。
- `plan`：尚未发生，绝不写成“我已经做过”。

删除源材料时必须清除或重算派生摘要、向量、关系画像和思考记录；不能只删除聊天原文。

## 8. 真人/历史人物模拟

PersonaPack 将生平时间线、价值冲突、表达方式、情境决策案例和知识范围分开。每条人格主张标注 source/evidence/confidence，而不是“某名人=冒险/自信”两三个刻板印象。

必须显式选择：历史某时点模拟，或继承资料后继续学习的数字角色。历史时点模拟要按当时可知信息检索，并做后见之明泄漏测试；给 LLM 一句“你不知道后来的事”不能保证知识隔离。人物的公共发言不等于其全部内心，未公开动机只可作为带不确定性的推断。

界面持续标明模拟身份，不能冒充真人对外发消息。私人材料仅在授权范围内使用。评价应优先使用未见过、且按时间切分的情境决策，而不是让模型复述其已知名言。

## 9. Harness 的正确性边界

单人格单写者。多个 Work 并发可以共享不可变快照，但只能回传事件或受验证的 MindPatch。稳定版本、权限 epoch、dialogue epoch 与候选有效期在生成后及 dispatch 前复查。

Outbox 状态是 READY → SENDING → SENT / UNKNOWN。收到服务成功回执才确认 SENT。崩溃/超时可能已发生外部效果，必须 UNKNOWN；仅在确认幂等和核实回执后才可恢复。模型调用重试与有副作用的 tool 重试是两回事。

全局 revision 是保守起点；高频桌面信号会让所有草稿失效。正式版要事件合并、按相关性切分 epoch、turn-taking，并给主动任务设置饥饿监测。不要持有 actor 锁等待网络。

长期 agent 的跨上下文连续性依赖显式进度、产物和可恢复状态，不能只靠上下文压缩；这也是公开长任务 harness 经验强调的方向。[S11]

## 10. 技术选型

| 层 | 建议 | 原因 |
|---|---|---|
| 常驻内核 | 延续 Rust + Tokio | 保持 Main/Work、事件循环、ToolRuntime 一致 |
| Jev Provider | reqwest + serde，原始 REST，固定模型与题目版本 | 减少实验 SDK 契约变化影响 |
| 对话/反思 | 现有 LLM Provider/Agent SDK，角色分工而非不同人格 | 共享证据与状态，便于替换模型 |
| 状态 | 单机 SQLite WAL，单写者 | 首版不引入分布式状态复杂性 |
| 检索 | SQL/全文检索起步，必要时加本地 embedding | 先解决来源、时效、删除，再追求大规模向量召回 |
| 桌面 UI | Tauri 2 + TypeScript/React | 统一信任 UI、通知和受限命令；仍需宿主鉴权 |
| 电脑感知 | 应用事件、可访问性树、浏览器 DOM 优先，视觉兜底 | 先形成证据，再给 Jev 做判断 |
| 校准评测 | Python 离线流水线、事件回放、人工评测 | 与在线权限内核分离 |

SQLite WAL 支持读写并行，但仍只有一个写者，且有 checkpoint 运维问题。[S12] Tauri capabilities 约束窗口/WebView 权限，不自动保护不安全的 Rust 后端代码。[S13] 生成 HTML 不应放入具有宿主权限的主 WebView；使用隔离渲染和显式 typed action bridge。

## 11. Jev 与平台风险

官方当前明确提到英文效果最好，中文需独立验证；数值和日期比较留给代码。state 中的恶意指令仍可能改变结果；长而无关的输入也损伤准确率。[S2][S6] 所有这些都使 Jev 不适合作为权限裁判。

线上出网授权不等于资料可以发给任何供应商；要做字段级数据处理策略。TypeSafe 的不用于训练声明不等价默认零保留，仍需核实合同和数据处理约定。[S2]

固定模型版本、题目版本、policy 版本和人格版本；用相同回放集做升级回归。接口预留本地分类器、NLI、小模型 JSON 等替代实现，避免人格生命史绑定某一家 SaaS。

## 12. 评测与里程碑

规则-only、本地分类器/零样本分类、小型生成模型结构化判断、Jev 在同一候选和事件集比较。记录实际部署端到端 P50/P95、调用成本、错误打扰/天、值得说而漏掉的事件、Brier/ECE、风险-覆盖率、语料时效泄漏、人格一致性、无来源记忆和重复动作。

校准应使用目标领域标签并与最终测试集分开；经典温度缩放方法不代表能自动解决所有域偏移。[S9] 不回复往往是缺失反馈，不等于厌恶。用户愿不愿被打断也不是唯一目标，不能用聊天时长/黏性代替尊重与价值。

阶段 A：事件、权限、状态、回放与影子决策。
阶段 B：明确授权下的低频主动消息，对话租约、撤销和反馈。
阶段 C：自定兴趣目标、真实探索、分层记忆、证据约束反思、状态变化因果测试。
阶段 D：时间线约束的 PersonaPack，跨情境人格评测、数据授权与风格隔离。

最终验收不是“每隔一分钟说句话像某名人”，而是“经历可追踪，观点有依据，目标有连续性，状态能影响选择，边界始终可控”。
